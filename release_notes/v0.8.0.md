# v0.8.0 - Reject unknown fields in request payloads

Released 2026-09-17.

**Breaking for clients that send fields the schema does not define.**
Those requests previously succeeded with the value discarded; they now fail
with a 422 naming the field.

See [CHANGELOG.md](../CHANGELOG.md) for the itemised list.

## Upgrading

No migration, no schema change.
`git pull` and restart.

The risk is entirely on the client side.
If anything is posting fields this API does not define - a stale field name,
a forward-compatible client sending tomorrow's schema, a copy-pasted payload
carrying extras - it worked before and will now return 422.

To find out before deploying, replay a sample of real payloads against the
new build and watch for 422s with `"type": "extra_forbidden"`.

## Why

Pydantic defaults to `extra="ignore"`.
That produced two bad outcomes, neither of which told the caller what was
wrong:

```
POST {"title": "N", "descrption": "typo"}    201  - value silently discarded
PUT  {"descrption": "typo"}                  400  - "No fields provided to update"
```

The second is the worse one.
The caller *had* provided a field; they had simply spelled it wrong, and the
error pointed at the opposite problem.

Now:

```
POST {"title": "N", "descrption": "typo"}    422  loc=['body','descrption']
                                                  "Extra inputs are not permitted"
PUT  {"descrption": "typo"}                  422  same
PUT  {}                                      400  unchanged - no unknown field
PUT  {"body": "ok"}                          200
```

## Scope

`extra="forbid"` is set on the 24 write-side classes - every `*Create` and
`*Update` across the twelve resources.

The response schemas are **deliberately left permissive**.
They are validated from ORM objects rather than caller-supplied dicts, so
forbidding extras there buys nothing and risks breaking serialisation.

## Verifying the tests

`tests/test_payload_validation.py` adds 39 tests, parametrised across all
twelve resources.
Reverting the config to `extra="ignore"` fails 25 of them.
The 14 that pass either way are `test_create_still_accepts_known_fields`,
which exist to catch a typo in the config breaking every write rather than to
test the new behaviour.
