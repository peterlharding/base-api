# v0.9.0 - Authentication

Released 2026-09-17.

**Breaking. Every `/api/v1` CRUD route now requires a bearer token.**
A client that worked against 0.8.1 without authenticating receives 401.

See [CHANGELOG.md](../CHANGELOG.md) for the itemised list.

## Upgrading

No migration. Two things to do:

1. **Set `JWT_SECRET`** in the repo-root `.env`.
   There is deliberately no default, and the application refuses to issue or
   verify a token without one.
   HS256 requires at least 32 bytes:

   ```sh
   python -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

2. **Re-seed**, because the sample passwords moved from SHA-256 to bcrypt:

   ```sh
   make seed-reset
   ```

Any real credentials will need rehashing:

```sh
python -m app.auth.password '<password>'
```

## Obtaining a token

```sh
curl -X POST http://127.0.0.1:8087/api/v1/auth/authenticate \
  -u 'api@performiq.com:sample-password' \
  -H 'Content-Type: application/json' \
  -d '{"username":"plh","password":"sample-password"}'
```

```json
{"token": "...", "refresh_interval": 3600, "user": {...}}
```

Then `Authorization: Bearer <token>` on every other request.

In Swagger, **Authorize** takes both: the Basic box for the client
credential, the Bearer box for the token.

## Why two layers

HTTP Basic identifies the *client* against `api_credentials`; the JSON body
identifies the *user* against `application_user`.
Both must pass.
A stolen user password is not by itself enough to mint a token, because the
caller also needs the client credential.

`/auth/refresh` waives expiry within 24 hours but never waives the signature,
so an expired token can be exchanged for a fresh one while a forged one
cannot.

## What stays open

- `/health` - a liveness probe that required a token would not be one.
- `/api/v1/auth/authenticate` and `/refresh` - nothing could obtain a token
  otherwise.

A test asserts the second with real credentials and a 200, rather than
merely checking for a non-403: the distinction matters, because
`authenticate` returns 401 to a request with no Basic Auth regardless of
whether it sits behind a bearer dependency.

## Notes for the curious

**Sample passwords.** `sample-password`, for `admin`, `plh` and the
`api@performiq.com` client credential, documented in both seed files.
The previous SHA-256 digests could not be reversed, so the plaintext was
chosen rather than preserved.

**Why routes depend on a shared instance.** `Depends(JWTBearer())` builds a
fresh object per route, and `app.dependency_overrides` keys on identity, so
there is nothing for a test to target.
Every test touching a protected route would have to mint a real token and
insert a user row that list and pagination assertions would then have to
account for.
The shared `jwt_bearer` avoids that.

**The signing secret has no default.** A committed fallback is a secret
everyone with the repository knows, and it would be used silently by any
deployment missing a `.env`.

## Known gaps

- **No logout.** `token_blacklist` exists, tokens carry a `jti`, and the
  bearer dependency checks the blacklist - but no endpoint writes to it.
- **Nothing records sign-ins.** `login_session` is never written.
- **Nothing writes `audit_log`.**
- **`created_by_id` / `updated_by_id` are still NULL everywhere**, though the
  bearer dependency now yields the acting user, so this is unblocked.
- `login_session`, `audit_log` and `instance_metadata` have no endpoints.
  The front end needs all three; see `TODO.md`.
