# v0.12.1 - Prune expired blacklist rows

Released 2026-09-17.

0.12.0 added logout, which writes a row to `token_blacklist` for every token
revoked.
Nothing ever deleted those rows.

Not breaking. No migration.

See [CHANGELOG.md](../CHANGELOG.md) for the itemised list.

## Upgrading

`git pull` and restart.

Existing expired rows are cleared the first time anyone logs out, or
immediately with:

```sh
make prune-blacklist-dry-run    # report what would go
make prune-blacklist            # delete it
```

## Why a row can be deleted

A blacklist entry only has to outlive the token it revokes.
Once the expiry has passed, the token fails validation on its own and the row
is answering a question nobody will ask.

Tokens live an hour, so rows become prunable quickly.

## Two triggers

**Logout prunes opportunistically.** The table only ever grows there, so it
is the one place that can keep it in check without introducing a scheduler.
The row logout has just written carries a future expiry and survives its own
pass - there is a test for precisely that, because it is the obvious way to
get this wrong.

**`make prune-blacklist`** covers what logout cannot: a deployment where
nobody signs out for a long stretch, leaving old rows in place.
`scripts/prune_blacklist.py` takes `--dry-run` and carries a cron line.

## The boundary

`expiry < cutoff`, so a row expiring at exactly the cutoff survives.
Arbitrary either way, but now decided rather than incidental, and pinned by a
test.

## Verified to fail when it should

| broken how | tests failed |
| --- | --- |
| prunes too much (`WHERE` dropped) | 4, including `test_pruning_does_not_unrevoke_a_live_token` |
| prunes nothing | 3, including `test_logout_prunes_but_keeps_its_own_row` |

The first is the one that matters.
Deleting a live revocation would silently un-revoke a token someone had
signed out, so there is a test that signs in twice, logs one token out,
prunes, and asserts the revoked token is still refused while the other still
works.

## Known gaps

- **Nothing runs `make prune-blacklist` automatically.** Logout covers the
  normal case; a cron entry covers the rest.
- **No revoke-all.** Signing out one device leaves the others signed in.
- **The API still does not write `audit_log` itself.**
